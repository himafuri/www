# Use domain terms and decisions

Use these documents to find the repository's domain vocabulary and architecture decisions:

- The root [glossary](../../GLOSSARY.md) defines domain terms.
- `docs/adr/` contains architecture decision records, or ADRs.

## Read domain docs before exploring

Read `GLOSSARY.md` and ADRs relevant to the area you will work in.

If these files or directories are absent, proceed silently. The `/domain-modeling` skill creates them when you resolve a term or decision.

## Use the glossary's vocabulary

Use glossary terms in issue titles, proposals, hypotheses, and test names. Avoid synonyms the glossary rejects.

If a needed concept is missing, check whether the project already uses another term. Record a missing term for `/domain-modeling`.

## Flag ADR conflicts

If a proposal contradicts an existing ADR, identify the ADR and explain why the decision should be reconsidered.
